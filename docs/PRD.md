# 커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트 명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

## 2. 기술 스택
- 프론트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프론트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 화면별 요구사항 (프론트엔드 UI)

### 4.1 주문하기 화면

#### 4.1.1 화면 개요
| 항목 | 내용 |
|------|------|
| 화면명 | 주문하기 |
| 목적 | 메뉴를 조회·선택하고 옵션을 지정한 뒤 장바구니에 담아 주문을 완료한다 |
| 진입 경로 | 앱 기본 화면, 헤더의 「주문하기」 탭 |
| 와이어프레임 | `assets/` — 주문하기 화면 와이어프레임 (COZY) |

한 페이지에서 **메뉴 선택 영역**과 **장바구니 영역**을 동시에 보여 주며, 페이지 이동 없이 담기·수량 확인·주문까지 이어진다.

#### 4.1.2 레이아웃 구조

화면은 위에서 아래로 세 구역으로 구성한다.

```
┌─────────────────────────────────────────┐
│  헤더 (로고 + 내비게이션)                  │
├─────────────────────────────────────────┤
│  메뉴 카드 목록 (가로 배치)                 │
├─────────────────────────────────────────┤
│  장바구니 (목록 + 총액 + 주문하기 버튼)      │
└─────────────────────────────────────────┘
```

| 구역 | 위치 | 역할 |
|------|------|------|
| 헤더 | 상단 고정(권장) | 브랜드 표시, 주문하기/관리자 화면 전환 |
| 메뉴 선택 | 헤더 하단 | 판매 중인 메뉴 카드 나열, 옵션 선택 후 담기 |
| 장바구니 | 하단 | 담은 상품 목록, 총 금액, 주문 제출 |

#### 4.1.3 헤더

| 요소 | 설명 | 요구사항 |
|------|------|----------|
| 로고/앱명 | 좌측 | 텍스트 **「COZY」** 표시. 클릭 시 주문하기 화면으로 이동(선택) |
| 탭 「주문하기」 | 우측 | 현재 화면일 때 **활성 스타일**(와이어프레임: 굵은 테두리 등으로 구분) |
| 탭 「관리자」 | 우측 | 클릭 시 관리자 화면으로 전환. 비활성 스타일 |

- 주문하기 화면에 있을 때는 「주문하기」만 활성 상태로 표시한다.
- 내비게이션은 라우팅 또는 탭 전환으로 구현하며, 새로고침 시에도 URL(또는 상태)로 현재 화면을 구분할 수 있으면 좋다(권장).

#### 4.1.4 메뉴 카드 (상품 선택 영역)

메뉴는 **카드 단위**로 가로(또는 반응형 그리드) 배치한다. 와이어프레임 기준 한 행에 여러 카드가 나란히 보인다.

**카드 구성 요소**

| 순서 | 요소 | 설명 | 비고 |
|------|------|------|------|
| 1 | 이미지 영역 | 메뉴 대표 이미지 | 없을 경우 플레이스홀더(와이어프레임: X 표시 박스) |
| 2 | 메뉴명 | 예: 아메리카노 (ICE), 아메리카노 (HOT), 카페라떼 | 서버/목 데이터에서 로드 |
| 3 | 가격 | 기본 가격, 천 단위 구분 + 「원」 | 예: 4,000원 |
| 4 | 설명 | 한 줄 요약 | 예: 「간단한 설명...」 — 데이터 없으면 생략 가능 |
| 5 | 옵션 | 체크박스 목록 | 메뉴별로 정의된 옵션만 표시 |
| 6 | 담기 버튼 | 「담기」 | 클릭 시 장바구니에 반영 |

**옵션 (와이어프레임 예시)**

| 옵션명 | 추가 금액 | UI |
|--------|-----------|-----|
| 샷 추가 | +500원 | 체크박스, 라벨에 가격 표기 |
| 시럽 추가 | +0원 | 체크박스, 라벨에 가격 표기 |

- 옵션은 **체크박스**로 다중 선택 가능(메뉴에 허용된 옵션만).
- 옵션 미선택 시 기본 가격만 적용한다.
- 옵션 목록·가격은 메뉴마다 다를 수 있으며, 하드코딩보다 **메뉴 데이터에 포함**하는 것을 권장한다.

**담기 동작**

1. 사용자가 옵션(선택)을 정한 뒤 「담기」를 누른다.
2. 동일 메뉴 + **동일 옵션 조합**이 장바구니에 이미 있으면 **수량 +1**한다.
3. 옵션 조합이 다르면 **별도 줄**로 추가한다.
4. 담기 후 장바구니 영역이 갱신된다(스크롤·하이라이트 등 피드백은 선택).

**표시 제외·비활성**

- 재고가 0이거나 판매 중지된 메뉴는 카드 비활성 또는 목록에서 제외 — 정책은 백엔드/관리자 화면과 맞춘다(초기에는 전 메뉴 노출 가능).

#### 4.1.5 장바구니 영역

| 요소 | 위치 | 설명 |
|------|------|------|
| 제목 | 좌측 상단 | **「장바구니」** |
| 항목 목록 | 본문 | 담은 상품별 한 줄(또는 블록) 표시 |
| 총 금액 | 우측(또는 목록 하단 우측) | **「총 금액 N원」** — 모든 줄 합계 |
| 주문하기 버튼 | 우측 하단 | **「주문하기」** — 주문 API 호출 |

**장바구니 한 줄 표기 형식 (와이어프레임 기준)**

- 텍스트: `{메뉴명} ({선택 옵션명 나열}) x {수량}` + 우측에 **해당 줄 금액**
- 예시:
  - `아메리카노(ICE) (샷 추가) x 1` → `4,500원` (4,000 + 500)
  - `아메리카노(HOT) x 2` → `8,000원` (4,000 × 2)
- 옵션이 없으면 괄호 부분 생략: `아메리카노(HOT) x 2`
- 줄 금액 = (기본가 + 옵션 추가액 합) × 수량

**총 금액**

- 장바구니 모든 줄의 금액 합을 실시간 계산한다.
- 예: 총 금액 12,500원

**빈 장바구니**

- 항목이 없을 때: 「장바구니가 비어 있습니다」 등 안내 문구 표시(권장).
- 「주문하기」 버튼은 **비활성** 또는 클릭 시 「담은 메뉴가 없습니다」 안내.

#### 4.1.6 주문하기 버튼 (장바구니)

| 항목 | 내용 |
|------|------|
| 라벨 | 주문하기 |
| 조건 | 장바구니에 1개 이상 항목 |
| 동작 | 주문 생성 API 호출 → 성공 시 장바구니 비우기 및 완료 안내(토스트/알림/모달 중 택 1) |
| 실패 | 서버 오류·재고 부족 등 메시지 표시, 장바구니 유지 |

- 결제·인증은 범위 외이므로, 주문 완료는 **「주문이 접수되었습니다」** 수준의 확인으로 충분하다.
- 주문 데이터에는 메뉴 ID, 옵션, 수량, 줄별/총 금액이 포함되어야 한다(백엔드 스펙과 연동).

#### 4.1.7 데이터·상태 (프론트엔드)

| 상태 | 설명 |
|------|------|
| menus | 메뉴 목록(이름, 기본가, 설명, 이미지 URL, 옵션 정의) |
| cart | `{ menuId, menuName, options[], unitPrice, quantity }[]` 형태 권장 |
| loading / error | 메뉴 로드·주문 제출 시 로딩·에러 UI |

- 장바구니는 **주문하기 화면 세션** 동안 유지한다(새로고침 시 유지 여부는 선택, 기본은 비움).
- 가격 계산은 프론트에서 수행하되, 최종 금액은 서버 검증을 권장한다.

#### 4.1.8 UI/UX 가이드 (와이어프레임 준수)

- 언어: UI 문구 **한국어**
- 스타일: 와이어프레임 수준의 단순한 테두리·여백 중심(색·폰트는 추후 통일 가능)
- 메뉴 카드: 이미지·텍스트·옵션·버튼의 **세로 정렬** 유지
- 장바구니: 제목·목록·총액·버튼이 한 블록(박스) 안에 들어가 와이어프레임과 같이 구분

**반응형 (권장)**

- 좁은 화면: 메뉴 카드를 1~2열로 줄 바꿈, 장바구니는 하단 전체 너비 유지

#### 4.1.9 예외·엣지 케이스

| 상황 | 기대 동작 |
|------|-----------|
| 메뉴 목록 로드 실패 | 에러 메시지 + 재시도(권장) |
| 담기 직후 동일 옵션 다시 담기 | 수량만 증가 |
| 주문 중 네트워크 오류 | 장바구니 유지, 재시도 안내 |
| 주문 성공 | 장바구니 초기화, 관리자 화면에서 주문 목록에 반영(백엔드 연동) |

#### 4.1.10 수용 기준 (Acceptance Criteria)

- [ ] 헤더에 COZY, 「주문하기」(활성), 「관리자」가 보이고 관리자 탭으로 이동할 수 있다.
- [ ] 메뉴 카드에 이미지(또는 플레이스홀더), 이름, 가격, 설명, 옵션 체크박스, 「담기」가 있다.
- [ ] 옵션 선택에 따라 담긴 항목의 단가가 반영된다.
- [ ] 동일 메뉴·동일 옵션 조합 담기 시 수량이 합산된다.
- [ ] 장바구니에 항목명·옵션·수량·줄 금액이 와이어프레임 형식으로 표시된다.
- [ ] 총 금액이 모든 줄의 합과 일치한다.
- [ ] 장바구니가 비어 있을 때 주문하기가 불가하다.
- [ ] 주문하기 성공 시 장바구니가 비워지고 사용자에게 완료가 안내된다.

#### 4.1.11 추후 확장 (본 화면 범위 외, 참고)

- 장바구니 항목 삭제·수량 직접 수정 버튼
- 메뉴 카테고리·검색
- 주문 완료 후 주문 번호 표시

### 4.2 관리자 화면

#### 4.2.1 화면 개요

| 항목 | 내용 |
|------|------|
| 화면명 | 관리자 |
| 목적 | 주문 흐름을 한눈에 파악하고, 메뉴별 재고를 조정하며, 들어온 주문의 상태를 단계적으로 처리한다 |
| 진입 경로 | 헤더의 「관리자」 탭 |
| 와이어프레임 | `assets/` — 관리자 화면 와이어프레임 (COZY) |

한 페이지에서 **대시보드 요약**, **재고 현황**, **주문 현황**을 위에서 아래 순으로 제공한다. 주문하기 화면(4.1)에서 생성된 주문이 주문 현황에 표시되고, 대시보드 숫자와 연동된다.

#### 4.2.2 레이아웃 구조

```
┌─────────────────────────────────────────┐
│  헤더 (로고 + 내비게이션)                  │
├─────────────────────────────────────────┤
│  관리자 대시보드 (주문 단계별 건수 요약)     │
├─────────────────────────────────────────┤
│  재고 현황 (메뉴별 카드 + 수량 조절)        │
├─────────────────────────────────────────┤
│  주문 현황 (주문 목록 + 상태 변경 버튼)     │
└─────────────────────────────────────────┘
```

| 구역 | 위치 | 역할 |
|------|------|------|
| 헤더 | 상단 | 4.1과 동일. 관리자 화면에서는 「관리자」 탭 활성 |
| 관리자 대시보드 | 상단 본문 | 전체·단계별 주문 건수 표시 |
| 재고 현황 | 중단 | 메뉴별 재고 수량 조회 및 +/- 조정 |
| 주문 현황 | 하단 | 주문 목록 조회 및 다음 처리 단계 실행 |

#### 4.2.3 헤더

4.1 주문하기 화면과 **동일한 헤더**를 사용한다.

| 요소 | 관리자 화면에서의 동작 |
|------|------------------------|
| COZY | 좌측 표시(주문하기 화면 이동은 선택) |
| 「주문하기」 | 클릭 시 주문하기 화면으로 전환, 비활성 스타일 |
| 「관리자」 | **활성 스타일**(와이어프레임: 박스·굵은 테두리 등) |

#### 4.2.4 관리자 대시보드

| 요소 | 설명 |
|------|------|
| 섹션 제목 | **「관리자 대시보드」** |
| 표시 형식 | 한 줄 요약: **총 주문 / 주문 접수 / 제조 중 / 제조 완료** |
| 예시(와이어프레임) | `총 주문 1 / 주문 접수 1 / 제조 중 0 / 제조 완료 0` |

**지표 정의**

| 지표 | 의미 | 집계 기준 |
|------|------|-----------|
| 총 주문 | 아직 완료되지 않은 활성 주문 수 | 상태가 제조 완료가 **아닌** 주문 건수(권장). 또는 전체 누적 — 백엔드와 하나로 통일 |
| 주문 접수 | 접수 대기·접수 완료 단계 | 상태 = `RECEIVED`(또는 동등 값) |
| 제조 중 | 제조 진행 중 | 상태 = `IN_PROGRESS` |
| 제조 완료 | 처리 완료 | 상태 = `COMPLETED` |

- 숫자는 **주문 현황 목록·API**와 일치해야 하며, 주문 상태가 바뀔 때마다 **즉시 갱신**한다(폴링 또는 갱신 API 호출).
- 신규 주문이 들어오면 총 주문·해당 단계 카운트가 반영된다.

#### 4.2.5 재고 현황

| 요소 | 설명 |
|------|------|
| 섹션 제목 | **「재고 현황」** |
| 레이아웃 | 메뉴별 **카드**를 가로 나열(와이어프레임: 3개 — 아메리카노 ICE/HOT, 카페라떼) |

**재고 카드 구성**

| 순서 | 요소 | 설명 | 예시 |
|------|------|------|------|
| 1 | 메뉴명 | 주문하기 화면과 동일한 메뉴 이름 | 아메리카노 (ICE) |
| 2 | 재고 수량 | 현재 재고 | `10개` 형식 |
| 3 | 증가 버튼 | **「+」** | 클릭 시 재고 +1 |
| 4 | 감소 버튼 | **「-」** | 클릭 시 재고 -1 |

**동작 규칙**

- 「+」: 재고 1 증가 후 서버에 저장(또는 낙관적 업데이트 후 API).
- 「-」: 재고 1 감소. **0 미만으로 내려가지 않음** — 0일 때 「-」 비활성 또는 무시.
- 변경 성공 시 카드上的 수량과 주문하기 화면의 판매 가능 여부(4.1)가 일관되도록 한다.
- 로드 실패 시 에러 표시, 재시도(권장).

**초기 데이터**

- 와이어프레임 예: 메뉴당 10개. 실제 값은 DB/API에서 조회.

#### 4.2.6 주문 현황

| 요소 | 설명 |
|------|------|
| 섹션 제목 | **「주문 현황」** |
| 레이아웃 | 주문별 **한 줄(또는 한 블록)** 리스트, 최신 주문이 위에 오도록 정렬(권장) |

**주문 한 줄 표기 (와이어프레임 기준)**

| 영역 | 내용 | 예시 |
|------|------|------|
| 주문 시각 | 접수·생성 시각 | `7월 31일 13:00` |
| 주문 내역 | 메뉴·옵션·수량 요약 | `아메리카노(ICE) x 1` (복수 품목이면 `, `로 이어 붙임) |
| 금액 | 해당 주문 총액 | `4,000원` |
| 액션 | 현재 상태에 맞는 **다음 단계 버튼** | 와이어프레임: **「주문 접수」** |

- 옵션이 있으면 주문하기 화면과 동일하게 괄호 표기: `아메리카노(ICE) (샷 추가) x 1`
- 금액은 주문 시점 합계와 동일(천 단위 구분 + 「원」).

**주문 상태 흐름**

고객이 주문하기 화면에서 「주문하기」를 완료하면 관리자 화면 주문 목록에 나타난다. 관리자는 아래 순서로 상태를 진행한다.

```
[신규] ──(주문 접수)──> [주문 접수] ──(제조 시작)──> [제조 중] ──(제조 완료)──> [제조 완료]
```

| 상태 | 관리자 UI(버튼 라벨) | 클릭 후 |
|------|----------------------|---------|
| 신규(대기) | **주문 접수** | 주문 접수 |
| 주문 접수 | **제조 시작**(또는 동등 라벨) | 제조 중 |
| 제조 중 | **제조 완료** | 제조 완료 |
| 제조 완료 | 버튼 없음 또는 비활성 | — |

- 와이어프레임에는 「주문 접수」만 그려져 있으나, 구현 시 **현재 상태의 다음 액션 버튼 하나**만 노출하는 방식을 권장한다.
- 완료된 주문은 목록에서 숨기거나 하단·접기 처리 — 정책 선택(기본: 목록에 유지해도 됨, 대시보드「제조 완료」만 증가).

**빈 목록**

- 주문이 없을 때: 「접수된 주문이 없습니다」 등 안내(권장).

#### 4.2.7 주문·재고와 주문하기 화면 연동

| 연동 | 설명 |
|------|------|
| 주문 생성 | 4.1에서 주문 API 성공 → 관리자 주문 현황·대시보드에 반영 |
| 재고 | 관리자에서 재고 감소/증가 → 4.1 메뉴 판매 가능 수량(또는 품절 표시)과 동기화 |
| 주문 접수 이후 | 제조 완료 전까지 해당 주문은 대시보드「총 주문」 등에 포함(4.2.4 집계 기준과 일치) |

- 주문 시 재고 차감 시점(주문 생성 vs 주문 접수 vs 제조 완료)은 백엔드에서 정의하고, 프론트는 API 결과만 표시한다.

#### 4.2.8 데이터·상태 (프론트엔드)

| 상태 | 설명 |
|------|------|
| dashboardStats | `{ total, received, inProgress, completed }` |
| inventory | `{ menuId, menuName, stock }[]` |
| orders | `{ orderId, createdAt, items[], totalAmount, status }[]` |
| loading / error | 각 섹션별 로딩·에러 |

- 관리자 화면 진입 시 대시보드·재고·주문 목록을 **병렬 또는 순차 로드**.
- 주문 상태 변경·재고 변경 후 해당 섹션 + **대시보드 숫자**를 다시 맞춘다.

#### 4.2.9 UI/UX 가이드 (와이어프레임 준수)

- 언어: **한국어**
- 헤더: 4.1과 동일 컴포넌트 재사용
- 섹션: 제목 + 테두리 박스로 구역 구분(와이어프레임 스타일)
- 재고 카드: 메뉴명 · 수량 · `[+][-]` 가로 또는 세로 정렬
- 주문 줄: 시각 · 내역 · 금액 · 우측 액션 버튼

**반응형 (권장)**

- 재고 카드: 좁은 화면에서 1~2열 줄 바꿈
- 주문 목록: 긴 내역은 줄바꿈, 버튼은 우측 고정 또는 하단 배치

#### 4.2.10 예외·엣지 케이스

| 상황 | 기대 동작 |
|------|-----------|
| 주문 목록 로드 실패 | 에러 메시지 + 재시도 |
| 재고 0에서 「-」 | 동작 없음 또는 버튼 비활성 |
| 상태 변경 API 실패 | 이전 상태 유지, 오류 안내 |
| 동시에 여러 관리자(학습 범위) | 마지막 저장 우선 — 별도 락 없음 가능 |
| 신규 주문 폴링 | 주기적 목록 갱신(선택) 또는 화면 포커스 시 갱신 |

#### 4.2.11 수용 기준 (Acceptance Criteria)

- [ ] 헤더에 COZY, 「주문하기」, 「관리자」(활성)가 보이고 주문하기 탭으로 이동할 수 있다.
- [ ] 대시보드에 총 주문 / 주문 접수 / 제조 중 / 제조 완료가 와이어프레임 형식으로 표시된다.
- [ ] 대시보드 숫자가 주문 상태 변경과 일치한다.
- [ ] 재고 현황에 메뉴별 이름, `N개`, +/- 버튼이 있다.
- [ ] +/-로 재고가 변경되고 0 미만이 되지 않는다.
- [ ] 주문 현황에 시각, 메뉴·수량, 금액, 상태별 액션 버튼이 표시된다.
- [ ] 「주문 접수」 등 버튼으로 주문 상태가 다음 단계로 바뀐다.
- [ ] 주문하기 화면에서 생성한 주문이 관리자 주문 목록에 나타난다.

- 주문 목록 필터(날짜, 상태)
- 관리자 로그인
- 제조 완료 주문 목록 접기/페이지네이션
